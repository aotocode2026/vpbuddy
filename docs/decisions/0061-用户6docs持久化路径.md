# ADR-0061：用户 6docs 使用独立持久化目录

- 状态：Accepted
- 日期：2026-08-15
- 关联：Issue #1–#5 综合数据路径修复

## 背景

仓库的 `docs/` 存放 ADR、架构、产品说明等源码维护文档。历史部署又把
`VPBUDDY_DOCS_DIR` 指向 `/data/vpbuddy/server/docs`，导致会议生成的需求、架构、
任务、API、风险与 Demo 混入 Git checkout。更新或替换 `server/` 后，这些运行时
交付物可能被覆盖；回滚目录中的旧交付物也不会被当前 API 识别。

## 决策

1. 用户 6docs 固定存放在 `${VPBUDDY_DATA_DIR}/docs`；当前服务端部署值为
   `/data/vpbuddy/data/docs`。
2. 仓库 `docs/` 只存源码维护文档，不作为运行时 fallback。
3. `server.config` 是 `DATA_DIR` 与 `DOCS_DIR` 的唯一默认值来源；controller、
   dashboard 和 API 共享该配置。
4. 启动器要求 `VPBUDDY_DATA_DIR`、`VPBUDDY_DOCS_DIR`、`VPBUDDY_KB_DIR` 均为
   绝对路径，并要求 `VPBUDDY_DOCS_DIR=${VPBUDDY_DATA_DIR}/docs`。
5. 迁移只接受能由当前会议 JSON 验证的 meeting_id。迁移合并遇到非相同重名
   文件立即中止，不覆盖任一版本；原目录保留作回滚。
6. BFF 聚合接口统一使用 `_doc_payload` / `_doc_path`，Demo 路径为
   `{meeting_id}/demo/demo.html`，不再误查 `demo.md`。

## 被否决的方案

- 继续使用 `server/docs`：checkout 不是持久化边界，根因仍存在。
- 用软链接兼容旧路径：隐藏错误配置，且更新源码时仍可能误操作用户数据。
- 按“与 GitHub docs 文件名不同”迁移：会把 E2E、STREAM 和历史测试目录误认成
  用户数据，无法证明归属。

## 影响

- 部署切换前必须合并 active 与 rollback 中属于当前 meeting_id 的目录。
- 切换后健康检查之外，还需验证 API 返回 `stored`、Markdown 正文以及 Demo HTML。
- 数据备份应同时包含 `/data/vpbuddy/data` 与 `/data/vpbuddy/kb`；替换
  `/data/vpbuddy/server` 不再影响用户交付物。
